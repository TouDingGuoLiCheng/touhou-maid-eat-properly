# PixelLab 稳定出图流程

面向 Cursor 里通过 MCP 调 PixelLab 生成/改图时使用。目标：**一次提交 → 轮询 → 下载落盘**，避免连环换方案。

---

## 1. 标准闭环（默认就走这条）

```
确认需求（尺寸 / 内容 / 是否只要一次）
    ↓
选工具并提交（create_* 或 edit_*）
    ↓
拿到 job_id
    ↓
get_image(job_id) 轮询至 completed（约 10–40s）
    ↓
用返回的 download URL 保存到本地（如 docs/assets/）
    ↓
展示结果给用户，停住等反馈
```

**完成标准**：本地有一张明确路径的 PNG；本轮不再自动重试、不换工具、不本地大改。

---

## 2. 工具怎么选

| 场景 | 用哪个 | 备注 |
|------|--------|------|
| 新图、文案能说清 | `create_image_pixen`（优先）或 `create_image_pixflux` | 封面/横幅可用 pixen；小精灵/图标 pixen 通常更稳 |
| 要多候选挑一张 | `create_image_pro` | 贵、慢；仅用户明确要「出一批再选」时用 |
| 在已有图上改局部（表情、去杂物等） | `edit_image` | 见 §4 体积限制 |
| 只修一小块、其余像素不动 | `inpaint_image` | 需 mask；比全图 edit 更可控 |
| 可旋转角色 / 地图物件 | `create_character` 等专用工具 | 不要用 freeform 图硬顶 |

查询结果：一律用 `get_image`。

---

## 3. 提交前检查清单

每次调用前对齐这几项（缺一项就先问用户，不要猜着连打多次）：

1. **尺寸与比例**（如封面 16:10 → 优先 `480×300`；pixflux 单边上限 400）
2. **背景**（纯色 / 透明 / 场景——写进 description，不要事后靠本地糊）
3. **主体**（角色特征、道具、表情）
4. **生成次数**：用户说「只生成一次」→ 本轮只提交 **1** 次 MCP 生成
5. **落盘路径**（默认 `docs/assets/`，文件名带用途与版本，如 `cover_16x10_v3.png`）

---

## 4. 带图调用（不稳定的主因）

理想闭环本身稳；**把大图 base64 塞进 MCP 参数**才容易超时/失败。

### 4.1 能不带图就不带图

反工若需求能用文字说清（例：「纯色奶油底 + 开心表情 + 酒狐持送餐盒，16:10」），优先 **纯文案 `create_*` 一次生成**，不要为了「像上一张」强行 `edit_image`。

### 4.2 必须带参考 / 编辑时

1. 先把原图缩到工具允许的尺寸（edit 常见到约 512；pixflux init 单边 ≤400）
2. 用最近邻缩放保留像素风：`Image.NEAREST`
3. 再 base64；**payload 过大就先缩图，不要原分辨率硬塞**
4. 提交失败 → **停下来告诉用户**（失败原因 + 建议：缩图重试 / 改纯文案），**禁止**立刻改成 inpaint / 本地抠图 / 换模型连环打

### 4.3 禁止的「不稳定套路」

- 同需求连续换：`edit_image` → `pixflux` → `inpaint` → 本地 flood-fill
- 用 `PLACEHOLDER` 假装传了图
- 用户说「只生成一次」却并行开多个 job
- 失败后不汇报、闷头重试超过 **1** 次（第 2 次必须先征得用户同意）

---

## 5. 下载与落盘

1. `get_image` 返回 `completed` 后取 download URL（形如 `https://api.pixellab.ai/mcp/images/<job_id>/download`）
2. 下载到约定路径，打印确认 `saved <path>`
3. 向用户回报：**路径、尺寸、本轮用的工具与简要 prompt 意图**
4. 临时文件（`.tmp_*_b64.txt`、`.tmp_*_payload.json`）用完可删，勿当资产提交

---

## 6. 本项目常用规格

| 用途 | 建议尺寸 | 工具倾向 | 落盘示例 |
|------|----------|----------|----------|
| MC 百科 / 封面横幅 16:10 | `480×300` | `create_image_pixen` | `docs/assets/cover_16x10_vN.png` |
| 小头像 / 图标 | `128×128`，常透明底 | `create_image_pixen` / pixflux | `docs/assets/avatar_*.png` |
| 基于现有封面微调 | 缩到 ≤400 宽再 edit，或纯文案重出 | 优先文案重出 | 新版本号，不覆盖旧文件 |

---

## 7. 失败时怎么说

对用户只报三件事，然后停：

1. **卡在哪**（提交超时 / base64 过大 / job 报错 / 下载失败）
2. **已消耗了几次生成**
3. **下一步选项**（A 缩图再 edit 一次 / B 改纯文案重出一次 / C 你先看现有文件）

不要在同一回合里自行选完并执行多条分支。

---

## 8. 一句话纪律

> **告诉 PixelLab → 等 `get_image` → 下载到本地 → 停。**  
> 复杂预处理和换工具，只在用户明确同意后才做。
