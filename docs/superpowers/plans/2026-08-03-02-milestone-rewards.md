| 项 | 决定 |

| 主方向 | 养成进度反馈（里程碑回礼） |
| 奖励形态 | 模组专属道具：信物 / 养成 / 增益 三类 |

## 2. 系统方案（推荐）

### 2.1 里程碑状态（每女仆）

在女仆 PersistentData（或现有 eat-properly 数据根）记录：

- 已跨越但未领取的里程碑等级列表
- 已领取的物品 id 集合（用于去重）
- 可选：每档实际抽出的物品（便于 GUI 显示「待领：xxx」）

好感升级时（已有 `MilestoneRegistry.onFavorLevelChange` 钩子）：若新等级命中表中档位且该女仆未处理过该档 → 标记「可领取」并抽奖锁定结果（领取前就定下物品，避免反复刷随机）。

### 2.2 GUI 领取

在现有「好好吃饭」页增加「里程碑回礼」区块：

- 列出待领取条目：等级 + 物品图标 + 领取按钮
- 领取：尝试进玩家背包；满则掉落在玩家脚边，并清空该条待领
- 已领取历史可折叠显示（第一版可只显示待领）

### 2.3 玩家三饰品槽

- 模组自有容器 / Capability，随玩家持久化与死亡规则（默认：**死亡掉落与原版背包一致，可配置 keep**）
- GUI：独立小界面或从「好好吃饭」/玩家物品栏入口打开（实现阶段再定入口；验收要求「能稳定打开并穿脱」）
- 仅允许放入标记为 `eatproperly:trinket` 的增益（及约定可戴）物品
- 效果结算：每 tick / 事件读取三槽，按**单件定义的 stack policy** 合并

女仆侧：可戴展示的信物走车万女仆现有饰品槽；不强制实现新槽。

### 2.4 叠加策略（单件声明）

每件增益声明例如：

- `stack: additive`（数值相加，如 +HP）
- `stack: unique`（同 effect id 只生效一次，如永不饥饿）
- `stack: max`（取最大，如减缓饱食下降百分比）
