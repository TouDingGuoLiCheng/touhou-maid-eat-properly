### A1 · 幸福增益对女仆回饱食 — **待测**（代码已修）

**现象（原）**
- 女仆挂上「幸福」后，**没有**饱食度持续恢复。
- 同一效果对**玩家**可以恢复饥饿/饱食。

**根因**
- 正式提交的 `HappinessEffect` 最初只处理 `Player`；仅靠 `applyEffectTick` 给女仆加饱食不可靠（且易与「是否打进 jar」混淆）。
- 玩家饥饿恢复本身正常，不应改动。

**已做（隔离）**
- 玩家：仍仅在 `HappinessEffect.applyEffectTick` 里 `FoodData.eat`。
- 女仆：新建 `HappinessMaidSatietyHandler`，在 `LivingTick` 上检测幸福效果，按同一节奏 `SatietyData.addSatiety`（与日降/话术同一通道）。
- 不改饰品、进食 mixin、日降等其他模块。

**验收回写**
- [ ] A1.1～A1.3 换新 jar 后重测

### A9 · 工作餐/家餐 +8 好感与连吃 — **待查 / 待修**

**现象**
- 低饱食连吃时：**第一次**加了好感，**第二次**没加。
- 用户问：这个好感增加是不是有冷却？

**期望（原验收）**
- 每次实际工作餐/家餐进食固定 +8 好感点。

**代码线索**
- `MaidMealFavorMixin`：真吃时把 apply 点数改成 8。
- `FavorabilityManagerMixin`：仅在 `canAdd` 上，饥饿时绕过冷却以**允许开吃**；`apply` 内部仍可能按 TLM 规则上冷却，导致第二次真吃不再加点。
- **修复方向**：连吃 bypass 期间，每次真吃都应 +8；或饥饿 bypass 时 `apply` 也不因冷却吞点。

**验收回写**
- [ ] 连吃两次均 +8（或文档明确「每冷却周期只加一次」——若改产品规则需你确认；当前验收期望是每次进食 +8）

### N1 · 低饱食祈求给食 — **待做（新特性）**

**已定规格（2026-08-03 确认）**

| 项 | 规则 |
|----|------|
| 饱食 | 本模组饱食 **&lt; 8** |
| 背包 | **没有**可食用食物（与饥饿先吃判定一致） |

| 表现 | `setBegging(true)`；**走近**主人并**看向**主人（对齐 TLM `MaidBegTask` 体感） |
| 右键 · 索要对上 | 正好是当前索要食物 → **进背包 1 个并完成索要** |
| 右键 · 池内非索要 / 无索要 | **B：只塞进背包 1 个**（不完成索要、不强制吃） |
| 右键 · 别的时候 | 非本祈求态时，**不能**靠「任意池内食物右键」走本特性直给（现有「有索要且手持指定食物右键完成」默认**保留**） |
